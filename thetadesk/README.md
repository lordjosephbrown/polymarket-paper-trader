# thetadesk

**Sell options premium with an AI copilot — on paper first.**

The trade most consistent options sellers make is boring on purpose: sell a 10–30 delta
put (or call) 25–50 days out on a liquid, high-IV name, collect the credit, take profit at
50%, manage at 21 days, roll when the strike gets tested. It wins often and loses big
occasionally, so the edge lives in selection, sizing, and discipline. That is exactly the
part an AI agent can help with — and exactly the part you should practise with paper money.

thetadesk is that practice desk, built for agents:

- **Scan** option chains and rank short puts/calls by probability of profit, annualized
  return on collateral, and liquidity
- **Analyze** any contract: Greeks, implied vol, breakeven, expected move, probability of
  touch, and a position size that respects a per-trade risk budget
- **Paper-trade** sells, closes, rolls, expiries and assignments in a SQLite ledger with
  cash-secured buying power
- **Manage** open positions with the standard rules (50% take profit, 2x stop, 21 DTE,
  tested strike) and get ranked roll candidates
- **Journal** win rate, P&L, profit factor, max drawdown, breakdowns by ticker and strategy

It never talks to a broker. Chains come in as JSON from wherever you get quotes — a
brokerage MCP connector, an API, a file — and every action is paper. No credentials, no
real orders, no real money.

Part of the [polymarket-paper-trader](../README.md) repo; lives entirely in `thetadesk/`.

## Install

```bash
cd thetadesk
pip install -e ".[dev]"        # Python 3.10+, depends only on click and mcp
thetadesk --help
```

## 60-second demo (synthetic sample chains)

```bash
thetadesk init --cash 100000
thetadesk scan examples/chains/NBIS.json examples/chains/META.json examples/chains/HOOD.json --right put --limit 5
thetadesk analyze examples/chains/NBIS.json --expiry 2026-10-16 --strike 52.5 --right put
thetadesk sell examples/chains/NBIS.json --expiry 2026-10-16 --strike 52.5 --right put --contracts 1 --notes "IV rank 58, 25 delta"
thetadesk positions examples/chains/NBIS.json      # marked to market + rule check
thetadesk manage examples/chains/NBIS.json --apply  # take profits / stop out / settle
thetadesk stats
```

The files in `examples/chains/*.json` are **synthetic** — generated by
`examples/make_sample_chains.py` from Black-Scholes with a volatility skew so every number
is internally consistent. `examples/chains/robinhood-2026-09-11/` holds **real** chains
for NBIS, META and HOOD (two expirations, strikes around the 10–30 delta zone) built from
Robinhood quotes at the 2026-09-11 close with `chain_from_robinhood`; they are a snapshot,
so use them to see real shapes and numbers, not to trade from.

```bash
R=examples/chains/robinhood-2026-09-11
thetadesk scan $R/NBIS.json $R/META.json $R/HOOD.json --right put --limit 5
```

Every command prints a JSON envelope: `{"ok": true, "data": ...}` or
`{"ok": false, "error": "...", "code": "..."}`.

## The AI loop

With thetadesk running as an MCP server next to a broker connector, the agent does the
whole cycle and a human keeps the final say on anything real:

```
broker tools ──► chain JSON ──► scan_chains ──► analyze_option ──► paper_sell
                                                                       │
fresh chain JSON ──► manage_positions ──► CLOSE / EXPIRE / ASSIGN (applied)
                                     └──► ROLL (candidates only) ──► paper_roll
                                                                       │
                                        stats / journal / export_journal ◄┘
```

1. **Find underlyings.** Use the broker's scanner (or your own list): high implied
   volatility, healthy options volume and open interest, no earnings inside the holding
   window. With Robinhood's scanner tools, for example, that is a scan on
   `FILTER_TYPE_IMPLIED_VOLATILITY` (decimal, `0.6` = 60%), `FILTER_TYPE_TOTAL_OPTIONS_VOLUME`,
   `FILTER_TYPE_TOTAL_OPEN_INTEREST` and `FILTER_TYPE_EARNINGS_DATE` — always confirm the
   exact filter names with the connector's filter-spec tool first.
2. **Fetch chains.** Pull the expirations, contracts and quotes for each underlying
   (on Robinhood: `get_option_chains` → `get_option_instruments` for the expirations
   you want, page by page → `get_option_quotes` for those contract ids, plus
   `get_equity_quotes` for spot and `get_earnings_results` for the next earnings date).
   Hand the raw pages to `chain_from_robinhood`; it joins contracts and quotes by
   instrument id and returns the chain every other tool accepts. Any other source can
   use the plain chain layout from `chain_format`.
3. **Scan and pick.** `scan_chains` ranks every contract that passes the filters.
   `analyze_option` gives the full picture for one contract plus a size from the account's
   risk budget (default: 5% of the account per position).
4. **Paper-sell** with `paper_sell`. Write the thesis into `notes`; it lands in the journal.
5. **Manage** on every heartbeat: fetch fresh chains, call `manage_positions` (with
   `apply=true` to execute closes and settlements). Rolls are only ever *proposed*, with
   ranked candidates; the agent or the human executes one with `paper_roll`.
6. **Review** with `stats` and `journal`. Win rate by ticker and strategy, average
   credit, days held, profit factor and drawdown are what tell you whether the process works.

Going live is deliberately outside this tool: once the paper record is convincing, the
human reviews and places real orders through the broker's own order tools.

### MCP setup

```bash
thetadesk-mcp                 # stdio transport
```

```json
{
  "mcpServers": {
    "thetadesk": { "command": "thetadesk-mcp" }
  }
}
```

Set `THETADESK_DATA_DIR` to move the ledger (default `~/.thetadesk/<account>/paper.db`).
Works with both the v1 (`FastMCP`) and v2 (`MCPServer`) MCP Python SDKs.

### MCP tools

| Tool | What it does |
|------|--------------|
| `init_account` | Create or reset the paper account (default $100k) |
| `get_balance` | Cash, collateral in use, buying power, realized P&L |
| `reset_account` | Wipe everything |
| `chain_format` | The chain JSON layout, with an example |
| `chain_from_robinhood` | Join Robinhood contract pages and quote pages into a chain |
| `scan_chains` | Rank short-option candidates across one or more chains |
| `analyze_option` | Greeks, probabilities, breakeven, return on collateral, position size |
| `size_for` | Contracts that fit a per-position budget and buying power |
| `paper_sell` | Sell to open at bid (or mid); reserves collateral |
| `paper_close` | Buy to close at a price or at a fresh chain's ask |
| `paper_roll` | Close and re-open at a later expiry (optionally a new strike) |
| `paper_settle` | Expire worthless or cash-settle an assignment |
| `paper_positions` | Open positions, marked and rule-checked against supplied chains |
| `manage_positions` | Apply the management rules; execute closes/settlements with `apply` |
| `stats` | Win rate, P&L, profit factor, max drawdown, breakdowns |
| `journal` | Trade log, newest first |
| `export_journal` | Trades or positions as JSON or CSV |

## Chain JSON

```json
{
  "underlying": "NBIS",
  "spot": 61.4,
  "as_of": "2026-09-11",
  "earnings_date": "2026-11-12",
  "iv_rank": 58,
  "options": [
    {"expiry": "2026-10-16", "strike": 52.5, "right": "put",
     "bid": 3.05, "ask": 3.30, "iv": 0.97, "delta": -0.25,
     "open_interest": 2364, "volume": 425, "id": "optional-instrument-id"}
  ]
}
```

- `underlying`, `spot` and `options` are required; `as_of` defaults to today.
- `iv` and `delta` are optional. Missing IV is implied from the mid, missing delta is
  computed from IV; the candidate's `flags` say when that happened.
- Rows with no usable price are skipped and counted in `skipped_rows`.
- Robinhood-style names are accepted: `chain_symbol`, `last_trade_price`,
  `expiration_date`, `strike_price`, `type`, `bid_price`, `ask_price`,
  `implied_volatility` (decimal or percent), `open_interest`, `instrument_id`, `mark_price`.
- Pass one chain, a list of chains, or either as a JSON string.

### Building a chain from Robinhood

Robinhood's connector returns contracts and quotes separately, both keyed by instrument
id, and contract lists are paginated. `chain_from_robinhood` (MCP) and
`thetadesk chain-from-robinhood` (CLI) do the join:

```
chain_from_robinhood(
  underlying="NBIS",
  spot=<get_equity_quotes output or a number>,
  instruments=[<get_option_instruments page 1>, <page 2>, ...],
  quotes=[<get_option_quotes batch 1>, <batch 2>, ...],
  as_of="2026-09-12", earnings_date="2026-11-10")
```

Pages and batches can be passed as objects, lists, or JSON text. Inactive contracts and
other symbols are ignored; the result reports contracts without quotes and quotes without
contracts under `unmatched`. Quotes are only needed for the strikes you care about, so
fetch quotes for the 10–30 delta zone rather than the whole chain.

## How candidates are ranked

For every contract the scanner computes, from the chain's `as_of` date:

| Metric | Meaning |
|--------|---------|
| `credit` | What a seller collects: the bid (default) or the mid (`fill=mid`) |
| `pop` | Probability the short option is profitable at expiry (lognormal model, finishes beyond breakeven) |
| `prob_itm`, `prob_touch` | Probability of expiring in the money; ~2x that for touching the strike |
| `expected_move` | One standard deviation move of the underlying to expiry |
| `collateral` | strike x 100 — the cash-secured basis for puts *and* calls |
| `roc`, `annualized_roc` | credit / collateral, and the same scaled to a year |
| `score` | `pop x annualized_roc x (1 - min(spread_pct, 0.5))`, halved if earnings fall before expiry |

Default filters: puts and calls, 25–50 DTE, 0.10–0.30 delta, out of the money, open
interest ≥ 100, spread ≤ 15% of mid, credit ≥ $0.10, no earnings before expiry. Every
filter is a flag on `scan` / a parameter on `scan_chains`.

Short calls are sized and ranked on the same notional as cash-secured puts (the 100
shares that would cover them). A margin account would reserve less for a naked call; the
desk sizes by notional on purpose, so a "cheap" naked call cannot look better than the
put on the same strike.

## Management rules

Applied by `manage` / `manage_positions`, in this order:

| Rule | Default | Action |
|------|---------|--------|
| Expired | — | `EXPIRE` worthless, or `ASSIGN` (cash-settled at intrinsic) |
| Take profit | 50% of the credit decayed | `CLOSE` |
| Stop loss | loss ≥ 2 x credit | `CLOSE` |
| Tested | spot through the strike, or \|delta\| ≥ 0.40 | `ROLL` |
| Manage at 21 DTE | ≤ 21 days left | `CLOSE` if in profit, else `ROLL` |
| Otherwise | — | `HOLD` |

`ROLL` comes with ranked candidates from the same chain: the same strike further out
("out") and the strike closest to the position's opening delta ("out_and_down" /
"out_and_up"), each with the net credit of the roll and its own probability of profit.
Rolls are never executed automatically.

## Paper accounting

- Selling adds the premium to cash and reserves `strike x 100` per contract; buying power
  is cash minus reserved collateral.
- Closing subtracts the cost; realized P&L is `(credit - close) x 100 x contracts`.
- Expiry releases collateral. Assignment is cash-settled at intrinsic value (the desk
  does not carry stock positions), which is the P&L a real assignment would leave you with.
- Statistics use closed positions only; `premium_at_risk` on the balance is the open
  premium that could still be given back.

## Caveats

- **Not financial advice, and not a broker.** Everything here is paper. Real orders need
  options approval, margin, and a human.
- **Selling options can lose far more than the credit.** A 90% win rate does not protect
  you from the 10%; the stop-loss and sizing rules exist for that reason. Naked calls have
  unlimited risk.
- **Models are models.** Probabilities come from a lognormal (Black-Scholes) world with no
  dividends and no jumps; IV crush, gaps, and regime changes are not in it. A stale chain
  gives stale answers — always evaluate against fresh quotes.
- **Fills are assumed at the bid** (or mid) with no commissions or fees.
- Taxes are real; realized P&L is taxable.
